# 画面

`gui.exe` と VST3 の画面は**同じもの**（`src/ui/panel.*`）。GDI だけで描いていて、
外からは HDC を 1 枚渡すだけ。面が 2 つある。

```
make            gui.exe も一緒に作る
build/gui.exe <rom ディレクトリ> [--midi 番号] [--midi-b 番号]
              [--midiout 番号] [--midiout-b 番号]
              [--latency ミリ秒] [--size 1000x400] [--lcd]
build/gui.exe --list                      MIDI の入口と出口の一覧
build/gui.exe <rom> --boot --shot 絵.png   窓を出さずに絵だけ書き出す
build/gui.exe --shot 絵.png --grid        ROM 無しで絵だけ。方眼を重ねる
build/gui.exe --dump-layout panel.txt    いまの配置を書き出す
build/gui.exe <rom> --layout panel.txt   その配置で動かす（F5 で読み直し）
build/gui.exe <rom> --play 曲.mid         MIDI ファイルを流しながら動かす
build/gui.exe <rom> --lcd                 LCD だけを別窓いっぱいに表示する
```

`--lcd` は本体パネル、ボタン、状態表示、LCD の外枠を隠し、LCD の表示面だけを
窓いっぱいに表示する。既定の表示面は 878x270。窓を手で拡大縮小しても LCD の
縦横比を保つ。`--size 幅x高さ` と `--shot` も一緒に使える（窓では幅を基準にする）。

**PC で触る窓は別**。一覧（F3、右クリック、`--list-window`）とエディタ（F2、右クリック、`--editor`）。[doc/pc-editor.md](pc-editor.md)。

**パネルの絵は作り直さずに直せる**。位置も色も `panel.txt` という文字
ファイルに追い出してある。手順は [doc/panel-editing.md](panel-editing.md)。

## SmartMedia

**カードの差し込み口**（左下）を左クリックか右クリックすると品書きが出る。上の 3 つが SmartMedia。

* `新しい SmartMedia を作って差す` → 16MB / 32MB / 64MB / 128MB … 保存先を選ぶと、空のカードのファイル（`.img`）を作って差す。
  使う前に本体の `UTIL → CARD → Format` で書式化する
* `SmartMedia を差す...` … 前に作ったカードのファイルを差す
* `SmartMedia を抜く` … ファイルへ書き戻してから抜く

SAMPLING の SAVE / LOAD（ALL+SEQ など）と UTIL の CARD が使える。firmware が書いたところは 2 秒ごとと、
抜いたとき・gui を閉じたときにファイルへ書き戻す（書き換えたブロックだけ）。差していたカードは gui.ini に覚え、次に起動したときも差す。

ファイルの中身は SmartMedia の NAND の生の並び（1 ページ 512 バイト + 予備 16 バイト）。PC との出し入れは `tools/smcard.py` で:

```bash
python tools/smcard.py ls smartmedia.img
```

```bash
python tools/smcard.py put smartmedia.img drums.wav
```

```bash
python tools/smcard.py get smartmedia.img TAKE001.WAV
```

`info`（容量と空き）と `rm`（消す）もある。入れた WAV / AIFF は本体の SAMPLING → LOAD → WAV で読み込め、SAMPLING → SAVE → WAV で書いたものは
`get` で取り出せる。名前は 8.3 だけ（長い名前は作らない）。**gui で差しているカードは書き換えない**こと（gui が 2 秒ごとに書き戻すので、
どちらかの書き込みが消える）。抜いてから入れ、差し直す。

`render` にも `--card カード.img` がある（終わりに書き戻す）。

## MIDI ファイルを流す

同じ品書きの下半分。

* `MIDI ファイルを再生...` … ファイルを選んで流す
* `止める` … 止めて、鳴りっぱなしを消す（オールノートオフとダンパ解除）

* `口 3・4 を A・B に重ねて鳴らす` / `口 3・4 は鳴らさない` … 3〜4 口ぶんの MIDI ファイルの扱い（下）

MIDI ファイルを**窓に落としても**流れる（パネルの窓でも、エディタ・一覧・インサーションの
設定の窓でも）。いくつか落としたときは 1 つ目だけ。鳴っている曲があれば止めて流し直す。

トラックの出し先は、SMF のポート指定（`FF 21`）か、機器名（`FF 09`）が `A`〜`D` / `Port 1`〜`Port 4`
のものに従う。口 1 が MIDI IN A（パート 1-16）、口 2 が B（17-32）、口 3 が C（33-48）、口 4 が D（49-64）。
**口 C・D を使うには USB の口で起動する**（下の「MIDI の口」）。USB の口を使っていないときは、
3〜4 口の曲の口 3・4 は、既定では口 3 を A、口 4 を B に重ねて鳴らす（同じチャンネルを使うパートは混ざる）。
`口 3・4 は鳴らさない` を選ぶと、口 1・2 だけを鳴らす。選んだものは gui.ini に覚える。

最初から流したいときは

```bash
build/gui.exe <rom ディレクトリ> --play 曲.mid
```

送り先はエディタのつまみと同じ道（`ui::bridge` の輪）なので、パネルを
触っても混ざらない。**ここだけは時計を持つ**が、譜面を送る側が時計を
持つのは当たり前で、実機に MIDI ケーブルで繋いだ外の並べ機と同じ立場。
音源のほうは今までどおり、音声デバイスに頼まれた分だけ進む。

## MIDI の口を選ぶ

**動かしたまま画面から選べる**。パネルに描いてある `MIDI IN A` の
ジャックを左クリックするか、窓のどこかを右クリックすると品書きが出る。

同じ品書きの一番下に **「工場出荷状態に戻す...」** がある。確かめてから、
覚えている設定（ワーク RAM、`src/nvram.h`）を捨てて電源を入れ直す。
起動の引数 `--factory` でも同じことができる。

### 起動が速い（起動後の写し）

firmware の起動は音の時間で約 8 秒、実時間でも 1 秒近くかかる。**1 度起動し切った
状態を取っておいて、次からはそれを読み込む**（`src/bootcache.h`）。置き場は
`%LOCALAPPDATA%\S-MU2000\boot\<鍵>.bin` で、鍵は firmware・起動に使ったワーク RAM・
波形 ROM・状態の形の版から作る。どれかが変われば鍵が変わるので、古い写しは読まない。
消せば次の起動でまた作る。

**戻した状態は起動を回し切った姿と 1 ビットも違わない。** 同じ MIDI を書き出して
WAV がバイト単位で一致することを確かめてある（`render --bootcache`）。

実機の DIN 端子は **MIDI IN-A が 2 つ、IN-B、OUT、THRU**。USB だけで使える口として、ほかに
**IN の C・D**（パート 33-64）と **OUT の B 以降**がある。こちらは **IN A-D の 4 口**と、
MU2000 が自分で送り出す **OUT** を出している。どれも別々に選べる
（THRU A / B は、受けたものを外へ流すこちら側の出口）。

| | 中身 |
|---|---|
| MIDI IN A | ここから受けて**パート 1-16** を鳴らす。Domino などを繋ぐ口（[doc/domino.md](domino.md)） |
| MIDI IN B | 同じく**パート 17-32**。Domino の MIDI OUT B などを繋ぐ |
| MIDI IN C | **パート 33-48**。実機では USB だけの口 |
| MIDI IN D | **パート 49-64**。同じく USB だけの口 |
| MIDI OUT | **MU2000 が自分で送り出すもの**。SCI ch0 の送信線で、実機の OUT 端子と同じ。XG の問い合わせやダンプ要求への返事がここから出る。loopMIDI 越しに外のエディタへ返せば、外から読み書きできる |
| MIDI THRU A | A で受けたものを**そのまま外へ流す**。画面のつまみから出たコントロールチェンジや SysEx も一緒に出る |
| MIDI THRU B | B で受けたものを外へ。A と混ぜないので、外に繋いだ音源でもパートの割り振りが崩れない |

### A/D INPUT（サンプリングで録る音）

パネルの `A/D INPUT` のジャックを左クリックするか、右クリックの品書きの「A/D INPUT」で、
**録音デバイス**（WASAPI の共有モード）を選ぶ。左が AD1、右が AD2。44100Hz でなければ中で直す。
選んだ名前は `gui.ini` の `audio_in` に覚え、次に起動したときに開く。既定は「使わない」。
サンプリングの録音（SAMPLING → REC）と A/D パートに使う。A/D パートの音量は初期値が 0 なので、入力を鳴らすときは音量を上げる。

**実機と聴き比べるとき**は、MIDI THRU A を実機の 1 番目のポート、
MIDI THRU B を 2 番目に繋ぐ。並べ機から流した同じものが、こちらと実機の
同じパートに届く。

選んだものは `%LOCALAPPDATA%\S-MU2000\gui.ini` に**名前で**覚える。
番号で覚えると、USB の機器を挿し直したときに別の機器へ繋がってしまう
（実際、MU2000 を挿し直すと一覧の並びが変わる）。
`--midi` / `--midi-b` / `--midi-c` / `--midi-d` / `--midiout`（THRU A）/
`--midiout-b`（THRU B）/ `--midiout-mu`（OUT）を付けたときはそちらが勝つ。

**起動したときに開けなかった口は、名前を覚えたままにする。** loopMIDI を
起動し忘れた、機器を挿していなかった、というだけで選んでおいた口を忘れないように。
品書きから選び直すと、そちらに置き換わる。

### 音の出口（PHONES のジャック）

パネルの `PHONES` のジャックを左クリックか右クリックすると、音の出口を選ぶ品書きが出る。
選んだものは `gui.ini` の `output`（`digital` / `analog`）に覚える。既定はデジタル。

| 出口 | 中身 |
|---|---|
| デジタル | 実機の S/PDIF と同じ。一部の DPCM のサンプル（Alto Sax Legato の A2・A5 など）が持つ直流もそのまま出る。実機の S/PDIF を録って比べると、直流の大きさまで 0.1LSB で合う（issue #3） |
| アナログ | LINE OUT・PHONES のつもりで、DAC の後ろ（VOLUME のつまみより前）で直流を切る。1 次のハイパス（`src/analog_out.h`）。直流を持つ音を離した直後には、切っていた分が戻る低い揺れが出る |

**アナログの切れる周波数（3Hz）は仮の値。** 実機のアナログ出力はまだ録っていないので、
測ったら `analog_out::CUTOFF_HZ` を合わせる。

### 口が応答しないとき・MIDI が溢れたとき

**口を開くのは 2 秒で諦める。** 口の持ち主が固まっていると、Windows の
「開く」呼び出しが返ってこない。実際、Reason が loopMIDI の口を掴んだまま
落ちたあと、gui が起動の途中で止まったように見えた。いまは
「応答しない（loopMIDI やドライバが固まっているかもしれない）」と出して先へ進む。
loopMIDI を起動し直すか、機器を挿し直せば直る。

**THRU には、MIDI の線の 2 倍（1 秒に 6250 バイト）を超えて流さない。**
DAW と loopMIDI で MIDI の輪ができると、メッセージが際限なく増える。それを
THRU で実機へ流したら実機まで固まった。超えたぶんはメッセージ単位で捨て、
1 秒に 1 回「MIDI が多すぎるので捨てた」と出す。これが出たら輪を疑う。
MU2000 への受信の溜めにも上限（4MB）はあるが、輪の歯止めのためで、実際の演奏では届かない。
前は 65,536 バイトで捨てていて、DAW でホイールを回し続けると離鍵まで捨てて音が鳴りっぱなしになった。
実機は USB で同じ量を送っても何も失わず、遅れて全部さばく（issue #18、`src/mu2000.h`）。

### 口 C・D（パート 33-64）

IN の C・D は実機では USB だけの口で、USB 側の M37640 マイコンが受けている。
そのマイコンの ROM は吸えていないが、**SH-2 から見えるのは 2 番地と割り込み 2 本だけ**
だったので、そこに代役を置いて通るようにした（[doc/dump/usb.md](dump/usb.md)）。

firmware は **HOST SELECT が USB のときしか C・D を通さない**ので、
**gui も VST3/CLAP も既定で USB の口で起動する**（実機を PC に繋ぐときと同じ姿）。
DIN の口 A・B だけに戻したいときは gui なら `--host-midi`、プラグインなら
`plugin.ini` に `usb=0` と書く。**起動する前に決まる**ので、変えたら起動し直すこと。

USB の口のときは **A・B も USB 側を通る**。実機で HOST SELECT を USB にすると
DIN が黙るのと同じで、MU2000 が送り出す MIDI OUT も USB 側から出る（こちらでは
同じ「MIDI OUT」の口から取れるので、外から見た違いは無い）。
バイトの届き方も DIN の 31250bps から実機の USB の速さ（19,500 byte/s）になる。

loopMIDI で使うときは、**仮想ケーブルを口の数だけ作って**それぞれに割り当てる。
DAW では、プラグインが **MIDI 入力バスを 4 本**（`MIDI In A (Part 1-16)` から
`MIDI In D (Part 49-64)`）出しているので、トラックごとに送り先のバスを選ぶ。

窓のいちばん下の行に、いま繋がっている口が出ている。

MIDI 出力の Windows の API は待たされることがあるので、**音声スレッド
からは呼ばない**。音声スレッドは輪っかにバイトを積むだけにして、
別のスレッドが取り出して送る（`src/ui/midi_out.*`）。

## パネルの面

実機のフロントパネル。**実機の写真から採寸して並べてある**
（左に A/D INPUT と VOLUME と電源、中央に LCD と音色カテゴリ 18 個、
右に PLAY/EDIT/UTIL/EFFECT/SAMPLING/SEQ の 6 個と 3×3 のボタン、そして大きなダイヤル）。

| もの | 中身 |
|---|---|
| LCD | 本物の HD44780。字の絵は `roms/hd44780u_b04.bin` から引く。**文字が 2 行 × 20 桁 ＋ 絵記号のセグメント部**（下記） |
| LED | PLAY / EDIT / UTIL / EFFECT / SAMPLING / SEQ の 6 個と、MU / PLG-1〜3 の 4 個。firmware が点けたとおり。6 個は押しボタンを兼ねている |
| ボタン | 35 個。MAME の `mu500` の入力ポートと同じ配線 |
| 大きなダイヤル | **ホイールで回すか、掴んで上下に動かす**。実機のロータリーエンコーダ（ポート A の bit17/16）をそのまま動かしている。VALUE −/+ と同じ働き（下記） |
| VOLUME | **音源の外で掛ける最終の音量**。MIDI は出していない。掴んで動かす（縦でも横でも）か、上でホイールを回す。VST3 では Output パラメータと同じ値 |

キーボードでも押せる（MAME の割り当てと同じ）。

```
A=PLAY  E=EDIT  U=UTIL  F=EFFECT  S=MUTE/SOLO  [ ]=PART−/+
−  ==VALUE−/+  BackSpace=EXIT  Enter=ENTER  , .=SELECT◀▶
Q=SEQ  Z=AUDITION  X=SELECT  M=SAMPLING/MODE
```

LCD には firmware が書いたものがそのまま出る。起動すると
`◀000▶001 GrandP #01` のような演奏画面になる。

### 窓の分かれ方

**DDRAM の桁が、そのまま横一列に並んでいるのではない**。
ボタンを押して、どの桁が何に化けるかを追いかけて割り出した。

| DDRAM | どこに出るか |
|---|---|
| 0-8（両行） | 上の面のレベルメータ。1 マス 2 本で 18 本（A1 A2 と 1-16） |
| 9-16（両行） | 上の面の文字 8 桁。1 行目が音色名、2 行目が `▶000◀001` |
| 行 0 の 17-18 | **下の面の左**。部の番号「01」 |
| 行 1 の 17-19 | **その右**。「A01」 |
| 20-23（両行） | **下の面**。楽器のかたち。両行で 1 枚の絵 |
| 行 0 の 19 | 不明。まだ何なのか分かっていない |

割り出し方は、PART+ を押して 17-18 桁が `01`→`02` と動くこと、
VALUE+ で 9-16 桁の音色名と 2 行目の番号だけが動くこと、
GS リセットを送ると 9-16 桁が `GrandP #`→`GrandPno` に変わること
（TG300B の音色名は 8 文字ぶん使う）を見て決めた。

上の面は **2 行のあいだに隙間が無い**。レベルメータのバーが上下の行に
またがって伸びるので、空けるとバーが切れてしまう。桁のあいだは 1 点あく。

下の面は上の面とは並びが違う。

* 「01」と「A01」は**塊の中の桁を詰めて**並べ、塊のあいだを 2 点あける
* そこから 3 点あけて楽器のかたち。**この区画だけ点が細かく、正方形でもない**。
  横 20 点・縦 16 点ぶんの絵が、文字 1 行ぶんの高さに詰め込まれている
* その右は VOL / EXP / PAN / REV / CHO / VAR / KEY のセグメント
* いちばん右に XG / TG300B / PERFORM を示す小さな `▶` が 3 つ

**23 桁目は絵ではなく、決まった形のセグメントを点け消しする 64 個の
ビット**が入っている。パンのつまみ、リバーブ・コーラス・バリエーションの
扇、ノートシフトの 7 セグ、`MIC` `LINE` `BANK` `PGM#` `A1` `A2` `1`-`32` の
札、カーソルの `▼` が全部これで動く。番地は
[doc/lcd-segments.md](lcd-segments.md) に測って書いてある。

目盛りの番号はパートの番号なので、**それぞれのバーの真下**に置いてある。

窓の下に印刷されている札は、この並びと同じ位置に置いてある。

### レベルメータと表示器

firmware は**左の 9 マス**にレベルメータを描いている。
**1 マスに 2 本**のバーが入っていて、**バーの幅は 2 ドット**。
文字コードは

```
0x7f + 9 × 左のバーの点の数 + 右のバーの点の数     （どちらも 0-8）
```

上の行と下の行で**同じ表**を使う。バーは 2 行にまたがって伸びるので、
下の行が 8 まで埋まってから上の行が 1 から伸びていく。上の行まで届いて
いない側は 0。両方 0 のマスには空白 (`0x20`) が入る。

鳴っていないパートも 1 点だけ出る（左右とも 1、コード `0x89`）。
窓の下に点が 1 列並んで見えるのはこれ。

9 マス × 2 本 = 18 本で `A1 A2 1 2 … 16`。マスの左半分がパート 1・3・5…、
右半分がパート 2・4・6… に当たる。**表示の仕方によっては、右半分に
チャンネル B（17-32 トラック）の音量が出る**。

#### どうやって割り出したか

この LCD の字の絵は手に入らないので、firmware が書くコードを測った。
パート 1 とパート 2 だけを鳴らし、CC7 を 0 から 127 まで振って
DDRAM を読む。

| パート 1 | パート 2 | 上の行 | 下の行 | 読み方 |
|---|---|---|---|---|
| 0 | 0 | `20` | `89` | (1,1) 両方 1 点 |
| 48 | 0 | `20` | `bf` | (7,1) |
| 0 | 48 | `20` | `8f` | (1,7) |
| 48 | 48 | `20` | `c5` | (7,7) |
| 127 | 0 | `c7` | `cf` | 下 (8,8)、上 (8,0) |
| 127 | 64 | `c8` | `cf` | 上 (8,1) |
| 127 | 127 | `cf` | `cf` | 上下とも (8,8) |
| 16 | 127 | `87` | `a2` | 下 (3,8)、上 (0,8) |

左右がきれいに足し合わさり、上の行にも同じ表が使われていることが読める。
`0x80`-`0x88` も同じ表の一部（左が 0、右が 1-8）で、以前**幅いっぱいの
1 本バー**だと思っていたのは間違い。基準も `0x89` ではなく `0x7f` で、
バーが 1 点ずつ低く出ていた。

字の絵は本来 CGROM に入っているが、こちらが持っているのは ASCII だけの
代用フォントなので、**上の規則から起こしている**。本物の CGROM
（MAME の `mulcd.zip` の `hd44780u_b04.bin`）を置けばそちらが優先される。

パン／リバーブなどの表示器は右端の 2 行 × 4 マスにあり、こちらは
**firmware が CGRAM に書いた絵**なので最初から本物が出る。

見るには曲を流しながら絵を書き出す。

```
build/gui.exe roms --mid song.mid 60 --shot panel.png --size 2200x880
```

### ダイヤルと VALUE −/+ は同じもの

実機では大きなダイヤルと VALUE −/+ のボタンは同じ働きをする。
入り口はまったく別（ダイヤルはポート A、ボタンはスイッチの格子）だが、
firmware の中で同じところに落ちる。実測でも一致した。

| したこと | Volume の値 |
|---|---|
| 何もしない | 100 |
| VALUE+ を 3 回叩く | 103 |
| ダイヤルを +3 目盛り | 103 |
| ダイヤルを +1 目盛り | 101 |

長押しの連打も firmware 自身がやる（0.3 秒で +1、1 秒で +5、2 秒で +18 と加速）。
こちらは実機のスイッチをそのまま押しているだけなので、何も作り込んでいない。

画面でもそう扱う。**ホイールはどの面でもダイヤルとして効き**、
VALUE −/+ を押すとダイヤルの絵も一緒に回る。

**ダイヤルは掴んで上下に動かしても回せる。** パネルのダイヤルを押したまま、上へ動かすと +、下へ動かすと −（ホイールと同じ向き）。パネルの絵の目盛りで 4 画素ごとに 1 目盛り（窓の幅 1000 なら 100 画素で 25）で、窓を広げるとそれに合わせて伸びる。絵のダイヤルもホイールと同じく 1 目盛りで 15° 回る（`panel::dial_follow`、src/ui/editor.cpp）。

長押しと違って、**firmware はダイヤルを加速しない**。一気に 20 目盛り送っても 20 より多くは進まず、
音色を替えている最中などは取りこぼしもする（実機のダイヤルを速く回したときと同じ）。

### ダイヤルの中身

MAME はここを動かしていない（`pa_r()` が 0xffff を返すだけ）。配線の
覚え書きだけが残っていたので、実測で決まりを出した。

  * firmware は 2.5ms ごと（400Hz）にポート A を読む
  * **bit17 の立ち上がりで 1 目盛り、bit16 を立てておくと逆向き**
  * 素直な直交位相ではない
  * `0xffff` には bit16/17 が入っていない。MAME が返していた値は
    「ダイヤルが止まっている」に当たる

## エディタの面

SOL2 の XG エディタに倣った面。パートを 1 つ選び、そのパートのつまみを動かす。

**音源には手を入れていない。MIDI を送っているだけ**。つまみは XG の
パラメータチェンジ（マルチパート `08 pp xx`）を送る。実機に送るのと同じことを
しているので、パネルから触った結果とも矛盾しない。

パートは 32 個。上 2 段が口 A（1-16）、下 2 段が口 B（17-32）。

| 段 | つまみ |
|---|---|
| 1 | Volume / Pan / Dry / Reverb / Chorus / Variation |
| 2 | Cutoff / Resonance / Attack / Decay / Release / Vib Rate |
| 3 | Vib Depth / Vib Delay / Note Shift / Detune / Bank / Program |

つまみは上下にドラッグ、またはホイール。`XG リセット` は XG システムオン
（`F0 43 10 4C 00 00 7E 00 F7`）を送る。

**値は画面では覚えていない。音源に問い合わせて読み返している**
（パラメータの層、[doc/params.md](params.md)）。面を開いている間は 1 秒ごとに
選んでいるパートの塊を読むので、パネルや曲で変えた値もそのまま出る。
まだ読めていない値は `--` になる。前にあった Expression・Porta・Modulation の
つまみは、firmware に問い合わせる口が無い（読み返せない）ので外した。

### 効いていることの確かめ方

エディタで Program を 19 にしてからパネルの面に戻ると、LCD が
`◀000▶019 RockOrg#01` に変わる。画面 → bridge → 音源 → firmware → LCD と
一周しているのが目で見える。

## エフェクトの面

リバーブ／コーラス／バリエーション（XG のシステム側）と、
MU2000 の**インサーション 2 系統**。番地は実測で確かめたもので、
一覧と確かめ方は [doc/effects.md](effects.md)。

種別は `<` `>` で選ぶか、ホイールを回す。値はエディタの面と同じく音源から
読み返している。面の表に無い種別（パネルで選んだもの）は `TYPE 49-00` のように
番号で出る。「この画面を送り直す」は要らなくなったので外した。

## 中の作り

```
ui::panel     配置・描画・当たり判定。面の切り替えもここ
ui::bridge    画面と音源のあいだ。ボタンは atomic のビット、
              MIDI は輪、LCD の写しは seqlock。錠は使わない
ui::driver    音声スレッド側。ボタンを音源へ、MIDI を音源へ、写しを画面へ
```

音源は音声スレッドが回しているので、画面から直接触ってはいけない。
触れ合うのは bridge だけ。

## 窓を出さずに見た目を直す

`--shot` で PNG に書き出せる。窓を開けない場所（自動での確認、不具合の報告）で使う。

```
build/gui.exe roms --boot --shot panel.png --size 1000x400
```

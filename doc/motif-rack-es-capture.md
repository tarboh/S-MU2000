# MOTIF-RACK ES: 実機から取るものの段取り

ファームウェアに手を入れずに、実機から取れるものを取る段取り。使うのは取扱説明書に載っている口だけ
（パネルのバルクダンプ、ダンプ要求、プログラムチェンジ、ふつうの演奏）。
[motif-rack-es.md](motif-rack-es.md) の静的な読みの答え合わせと、足りない Data（音色）の穴埋めが目当て。

**まだ何も実機へ送っていない。** ここに書いた手順は計画で、数字（かかる時間など）は見積もり。

> 取ったバルクダンプと録音は配らないこと（中身はヤマハの音色と波形）。`roms/motif-rack-es/` に置けば git には入らない。

## 2026-10-13 の進み具合

Data List が手に入り、実機を USB でつないだ。**送ったのは Data List に載っているダンプ要求（`F0 43 20 7F 00 0E mm nn F7`）だけ。**

* USB-MIDI のドライバは今の Windows でも動いた。口は `Yamaha MOTIF-RACK ES-1`（入力 1 本、出力は -1 から -8）
* 道具: `tools/motif/mr_midi.py`（winmm を直接使う。`list`・`monitor`・`dump`）、`mr_voice.py`（取ったノーマルボイスを表にする）
* ダンプ要求は**プリセットも番地で直接取れる**。返ってくる区画の番地とバイト数は Data List の表のとおりで、チェックサムも全部合う
* 1 音色は 40 メッセージ・約 1.4KB。静かなときは 1 音色 0.8 秒、実機が演奏中だと 3 秒ほど
* 読み解きの確認: PRE1 の 1 番 `Full Grand` は、エレメント 1-3 が波形 3・4・5（`GrndStS`・`GrndStM`・`GrndStH`）をベロシティ 2-72・73-104・105-127 で分け、
  エレメント 4 が波形 1（`GrndStSw1`）を鍵 92 から上で使う。**波形の名前は Firm から取り出した表と合う**（Firm の表と Data List の番号が同じ並びだと確かめられた）
* デジタル出力は Babyface の SPDIF 入力（`rec.exe` の 0 番）に来ている。24bit の格子に乗っている

ヘッダの番地の 2 バイトめ（mm）と中身:

| mm | 中身 | nn |
|---|---|---|
| 00-05 | ノーマルボイス PRE1-PRE6 | 0-127 |
| 06 | ノーマルボイス GM | 0-127 |
| 08・09・0A | ノーマルボイス USER1-3 | 0-127 |
| 0F | ノーマルボイスの編集バッファ | 0 |
| 18・19 / 1F | プラグインボイス PLG1・PLG2 / その編集バッファ | 0-63 / 0 |
| 20 / 21 / 28 | ドラムボイス PRE / GM / USER | 0-63 / 0 / 0-31 |
| 2F | ドラムボイスの編集バッファ | 0 |
| 40 | パフォーマンス INT | 0-127 |
| 41 | マルチ USER | 0-127 |
| 4F / 5F | パフォーマンス / マルチの編集バッファ | 0 |

（Data List の表は 2 段組が崩れて文字起こしされるので、mm の並びと説明の並びを数で突き合わせて決めた。5F でマルチの編集バッファが、00 で PRE1 が返ることは実機で確かめた）

**取り終えたもの（2026-10-13）**: ノーマルボイス 1,280（PRE1-6・GM・USER1-3）、ドラムボイス 97（PRE 64・GM 1・USER 32）、パフォーマンス 128、マルチ 128、マルチの編集バッファ。
取れなかったものは 0。ノーマルボイスを `mr_voice.py` で表にすると、鳴るエレメントは 2,943 個、プリセット（PRE1-6 と GM）が使っている波形は 570 種類（1,859 本のうち）。
ユーザーのデータを取ったので、これがそのまま控えになる。

取ったものは `roms/motif-rack-es/capture/` の `voice/`・`drum/`・`perf/`・`multi/`・`edit/` に、`<mm>_<nn>.syx` の名前で置く。

## 注意: 2026-10-13 の録音には、6 秒ごとに 1 サンプルのずれが入っている

オーナーが「6 秒ごとにジッという音がする」と気づいた。正弦波を 90 秒鳴らしっぱなしにして録ると、**6.02 秒ごとに約 50 ミリ秒の乱れ**があり、
乱れの前後で正弦波の位相が**ちょうど 1 サンプルぶん**ずれていた（乱れの中は、同じ値が 2 回続く所と 1 つ飛ぶ所が交じる）。

* 周期は鍵を変えても 6.02 秒のまま（A3・A4・A5 で同じ）、鳴らし始めの時刻とも無関係、左右で同じ、無音のときは何も出ない
* つまり**音源の中の出来事ではなく、デジタルの受け渡しで 6 秒に 1 サンプルずつ足りなくなっている**。受ける側（Babyface）の時計が
  実機の時計に合っていない（差は約 3.8ppm）ときの形。**実機の故障ではない**、と見ている
* 直し方: Babyface の設定でクロックの元を光入力（SPDIF）にして、実機の時計に従わせる。**まだ直していない**（オーナーの設定なので触っていない）
* 影響: 音量・EG の時間・音程の測定は、乱れが短いので結果は変わらない。**波形の下録り（1〜296 番）は録り直す**
  （境目の見立てに、乱れが偽の境目として混ざる。録音そのものも 1 サンプルのずれを含む）。下の「2 回録って比べると差が 0.0008」も、このずれのせいかもしれない

### 録音と Firm の表の突き合わせ（数字）

EG の速さの表は 5 つ並んでいる（8C0DDA08・8C0DDC08・8C0DDE08・8C0DE008・8C0DE208、32bit × 128）。録音から出した時間を、表の同じ番号（127 − 時間のパラメーター）と比べた。

| 測ったもの | 録音から | 表の値 | 差 |
|---|---|---|---|
| アタック 96: 振幅がまっすぐ上がりきるまで | 56,231 サンプル | 8C0DDA08[31] = 58,361 | −3.6% |
| アタック 112 | 225,203 | 8C0DDA08[15] = 234,696 | −4.0% |
| アタック 127 | 824,634 | 8C0DDA08[0] = 873,373 | −5.6% |
| リリース 64: 255 目盛りぶん（95.96dB）下がる時間 | 34,733 サンプル | 8C0DDC08[63] = 34,950 | −0.6% |
| リリース 80 | 139,274 | 8C0DDC08[47] = 139,802 | −0.4% |
| リリース 96 | 557,977 | 8C0DDC08[31] = 559,206 | −0.2% |

* **8C0DDA08 は上がる側（アタック）の表、8C0DDC08 は下がる側（ディケイ・リリース）の表。**どちらも単位はサンプル数で、「255 目盛りぶん動く時間」
* 下がる側は 0.2〜0.6% の差で合う。**1 目盛り = 95.96 ÷ 255 = 0.376dB（0x10 = 6.02dB）**が、時間の側からも裏づけられた
* 上がる側は 4〜5% 短い。まっすぐ上がる部分の傾きから出した値なので、端の丸まりのぶんだと見ている
* 8C0DDE08・8C0DE008 は 8C0DDC08 とほぼ同じ中身（0 番と 127 番だけ違う）。8C0DE208 は別の形（8,388,096 から 4,210,495 までなだらかに減る）で、用途は未読

### EG の模型（`src/motif/swp50_eg.h`）

録音と表を突き合わせて、音量の EG を式にした。`src/motif/swp50_egtest.cpp` が実機の数字と比べる（16 件、全部通る）。

* **下がる側の表（8C0DDC08）は、式 `0x3FFF000 ÷ ((8 + (r & 7)) << (r >> 3))` と 1 以内で一致する**（r = 速さの番号）。
  つまりチップは、**高さを 26bit の数えで持ち、1 サンプルごとに `(8 + 下位 3bit) << 上位 4bit` ずつ進める**。
  数えの上位 8bit が高さ（0x10 = 6.02dB）で、その下の 6bit を足した 14bit が、Firm が読み戻している「今の高さ」と同じ幅になる
* 下がる側は dB でまっすぐ。模型と録音の差は 2% 以内（リリース 96 で、T の 25%・50%・75% の時刻に −24.0 / −48.0 / −72.0dB、録音は −24.4 / −48.5 / −72.6）
* 上がる側は振幅でほぼまっすぐ。T の 10%・25%・50% で振幅 0.10 / 0.25 / 0.50（録音は 0.105 / 0.245 / 0.499）、T でちょうど全開。
  75%・90% では録音のほうが少し大きい（0.79・0.915）ので、後半はわずかにふくらむ
* 上がる側の表（8C0DDA08）は、進みとの積が r & 7 ごとに 6.99〜7.34 × 10⁶ とばらつく（下がる側のようにきれいな式にならない）。模型は r & 7 ごとの定数 8 個で近似
* ディケイの時間 80 で音量 64 の高さへ: 模型は 3.05 秒、録音は 3.11 秒
* 表の 0 番は下がる側だけ「終わらない」（0x7FFFFFFF）。いちばん速い側は上がる側も下がる側も 129 サンプルで頭打ち

### 取ったデータのまとめ方（2026-10-13 追記）

* **エレメントの欄の表**を `tools/motif/mr_params.py` に書いた（発振 17 欄、アンプ 24 欄、音程 24 欄、フィルター 35 欄、EQ 6 欄、LFO 8 欄、共通 LFO の受け方 4 欄）。
  プリセットの鳴るエレメント 2,521 個を全部読むと、値の範囲が Data List の範囲と合う（フィルターの型 0-21、EQ の型 0-5、LFO の波形 0-2、パン 1-127 など）。
  実機で確かめた欄には OK の印を付けてある
* **ボイスの共通部分**も足した: 音量・モノ / ポリ・ピッチベンドの幅・ポルタメント・リバーブとコーラスへの送り、インサーションのつなぎ方、
  リバーブ / コーラス / インサーション 1・2 の型と 16 個のパラメーター。プリセットで読むと、ピッチベンドは +2 / −2（66 / 62）が 874 個、など値はもっともらしい。
  コントローラーの割り当てと共通 LFO の表はまだ。エフェクトの型は番号（上位 7bit・下位 7bit）のままで、名前との対応は付けていない
* `mr_voice.py 置き場 --json 出力先` で、全音色を名前つきの JSON にできる（`capture/voice_json/` に 1,280 個）
* **鍵ごとのサンプルの割り当て**は `tools/motif/mr_zones.py` で出す（`mr_sweep.py` が録りながら出す見立てより細かい）。
  高い鍵では比べる長さを短くしないと、同じサンプルでも重ならなくなる（最初の版はこれで、いちばん上の鍵を全部「境目」にしていた）。
  録れた 252 本では、ピアノが 33 区間、エレピが 14、オルガンが 14、ギターが 23（どれも真ん中の値）。合わせて 5,300 区間
* フィルターのカットオフが「1 目盛り 50 セント」だった件: Firm の読みで出した「上限 19050 セント」は、パラメーターに揺らしぶん（EG・LFO・キーフォロー）を
  足したあとの頭打ちと読めば矛盾しない（255 × 50 = 12,750 セントがパラメーターだけの幅）。確かめてはいない

  Firm の送りの計算（`値 × 係数 >> 7` を表に通す）と同じ形で、エレメントの音量にもう 1 つの量（127 より大きい係数）が掛かっているのだろう。**見立て**
* ただし途中（110〜96）の刻みは 0.29〜0.34dB で、表の 1 目盛り（0.376dB）より細かい。この見立てだけでは合わない。**エレメントの音量の正確な式はまだ分からない**

**→ 2026-10-14 に Firm を読んで決まった。原因はレベルスケーリング**（`motif-rack-es.md` の「音量の足し算」）。

* 掛かっていたのは 146/128 = 1.1406。雛形は土台の音色（PRE1 の 1 番 Full Grand）の**レベルスケーリングのずらしを直していなかった**。
  この音色のエレメント 1 は区切り点 60 / 66 / 78 / 91、ずらし 128 / 146 / 146 / 103（128 が 0）。測った鍵 69 では +18 が効く
* 1 刻みで測った区切り（110〜108、107、106〜104、103・102、101・100、99・98、97・96）は、`音量 × 146 ÷ 128` を切り捨てて表を引いた結果とぴったり同じ。

### チップの音量の式（2026-10-14。Firm の表と測定の突き合わせ）

**Firm の中に、ボイスの音量の「下げ幅 → 倍率」の表は無い。** 変換はチップの中でやっている。Firm から言えるのは次の 2 つまで。

* Firm の側の表は**本物の対数**で作ってある。8C0AAD3E は `−32 × log2(v ÷ 127)` の四捨五入（127 個のうち 113 個が一致、残りは ±1）。
  チップの曲がり方に合わせて作った表ではない（チップの式の逆関数を当てると 75〜109 個ずれる）
* チップへ流し込む曲線の表の 1 つ（8C0E75C0、257 語。エフェクトの型 8C219916 ほかが 8C21DB48 で送る）は、
  `1024 × 2^(i/16)` を「**指数（上のビット）+ 11bit の仮数**」に詰めたもの（1024・1069・1117 … 2048・2139 … 4096・4187（= 4096 + 91）…）。
  チップの中の数が指数と仮数に分かれていること、16 目盛りで 2 倍の対数を正確に直すには表が要ること、が分かる。
  ボイスの音量はこの表を通らない（ボイスの側に表を送る口は無い）ので、**仮数をそのまま振幅に使う近似**になっている、と読める

**式**（下げ幅 a は 8bit、0x10 で半分）:

```
倍率 = 2^−(a >> 4) × (1 − (a & 15) ÷ 31.25)          a = 0xFF は無音
```

Firm の計算（`motif-rack-es.md` の「音量の足し算」）で a を出し、この式に通すと、測った値と合う。

| 測ったもの | a の出し方 | 点数 | 式との差 | 本物の対数（a × 0.376dB）との差 |
|---|---|---|---|---|
| エレメントの音量 110〜1（15 点） | AD3E[音量 × 146 ÷ 128] | 15 | **0.01dB 以内** | 最大 0.43dB |
| 音色の音量 120〜16（7 点） | AD3E[127 × 音量 ÷ 128]（切り捨て） | 7 | **0.02dB 以内** | 最大 0.40dB |
| CC7・CC11 100 / 64 / 32 | AD3E[127 × 値 ÷ 128] | 3 | 0.01dB 以内 | 最大 0.31dB |
| AEG の高さ 120〜8（10 点） | AD3E[高さ] | 10 | 0.09dB 引くと 0.05dB 以内（全点に同じ 0.09dB が乗っている） | 最大 0.6dB |

* 前に「音色の音量は上と下の端で 0.2〜0.9dB ずれる」と書いたのは、**音量が表を直に引くのではなく、積の係数として入る**（127 × v ÷ 128 を切り捨ててから表）ことと、
  この式の曲がりで全部説明がつく（16 → 15 → a = 99 → 37.00dB。測定 37.00）。CC7・CC11 も同じ入り方
* 分母が 32 ではなく 31.25 なのは、「仮数は 32 分の 1 刻みで、**ほかに 0.75 目盛りぶんの下げがいつも足されている**」と置いても同じ式になる
  （(32 − m − 0.75) ÷ (32 − 0.75)）。どちらなのかは、この測定からは決められない
* 16 目盛りごとの境目（a = 15 → 16）は 0.52 → 0.50 で、段は 0.34dB。ほかの段（0.28〜0.33dB）とほぼ同じ大きさ
* 確かめていないもの: EG が動いている途中（下げ幅の端数）の倍率。送りの量（r = 0x20-0x27）が同じ式かどうか（→ パンも送り（Dry Level）も同じ式。送りは分母 32 で合う）

### 送りの量は同じ式か（2026-10-14。Firm の読みと、残っていた録音）

**Firm からは決められない。** 送り（r = 0x21・0x23・0x25・0x27）も、パン（r = 0x1C）も、音量（r = 0x14）も、Firm は同じ目盛り（0x10 で半分の 8bit）の値を
そのまま書くだけで、倍率へ直すのはどれもチップの中。Firm の側で言えるのは「同じ目盛りとして扱っている」まで。

* **パン（r = 0x1C）は、音量と同じ「振幅でまっすぐ」の式だった。** パン 32 / 96 のとき、Firm の表（8C0AB03E）では下がる側の下げ幅が **17**（0x11）。
  最初の晩の録音（`ref/04_pan032.wav`・`04_pan096.wav`）を測り直すと、下がる側は −6.296〜−6.307dB。
  まっすぐの式は −6.30dB（分母 32 で 6.296、31.25 で 6.303）、本物の対数なら −6.40dB。**0.1dB の差で、まっすぐの側に合う**
  （分母が 32 か 31.25 かは、この 1 点では分からない）
* **送りそのものを変えた録音は、まだ無い。** 前に確かめた「64 で 6dB、32 で 12dB」は下げ幅が 16 の倍数ぶん動く点で、どちらの式でも同じ値になる（見分けられない）
* **見分ける測定**: マルチモードでパートの **Dry Level**（Data List のパートの 0x15。Firm では 0 番の送り = `表 8C0AACBE[値] + 8` → r = 0x21）を変えて録る。
  127 のときを 0dB として:

  | Dry Level | 下げ幅 | 本物の対数なら | まっすぐの式（分母 31.25）なら |
  |---|---|---|---|
  | 120 | 9 | −0.38 | −0.38 |
  | 112 | 11 | −1.13 | −1.20 |
  | 104 | 13 | −1.88 | −2.10 |
  | 96 | 14 | −2.26 | −2.59 |
  | 90 | 16 | −3.01 | **−3.45** |
  | 80 | 19 | −4.14 | −4.33 |
  | 64 | 24 | −6.02 | −6.02 |

  90 のところで 0.44dB の差が出るので、1 回録れば決まる。ドライの送りにはいつも +8（下げ幅）が足されているので、
  まっすぐの式なら「ドライは 3.01dB ではなく 2.57dB 下がっている」ことにもなる

  ばらつきの大きい型（高域通過、LPF6、LPF18s）は、目盛りによって形が変わる。エミュレーターでは、共通の周波数から型ごとの形を作ることになる
* **共通の周波数の目盛り**: 1 目盛りの上がり方は、くり返しの中で約 100 セント → 約 20 セントと減っていく。大きく跳ぶのは 128・153・178・204 で、
  くり返しの幅は 25 と 26 が交互。1 つのくり返しでほぼ 1 オクターブ（26 目盛りで 2.02 倍）。平均すると 1 目盛り約 47 セント
* **205 から上の「1 目盛り約 137 セント」は LPF24D の −6dB の点で見た値だった。** 共通の周波数では、204→205 で 92 セント跳んだあと、1 目盛り 60 → 26 セントと減っていく。
  LPF24D の形が高い所で変わる（ナイキストに近づく）ぶんが、−6dB の点を大きく動かしていた
* **共通の周波数は、目盛り 230 から上で 7,380Hz に貼りつく**（サンプリング周波数の約 1/6）。チップのフィルターの周波数の上限らしい（**見立て**）
* 目盛り 50 より下は谷が浅く（−18〜−64dB）、値がばらつく
* 目盛り 190 ほどから上の高域通過の型は、基準にした 15〜18kHz の帯域そのものが動くので、−3dB / −6dB の点は当てにならない

### フィルターの形の模型（2026-10-19。`src/motif/swp50_filter.h`、確かめは `tools/motif/mr_filterfit.py`）

全部の型・目盛りの周波数特性（素通しとの差、1/48 オクターブの格子）に、単純な部品の組み合わせを当てはめた。レゾナンス 0 のときだけ。

* **目盛りごとの係数 g は全部の型で共通。** LPF24D の録音に「1 次の低域通過 `y += g (x − y)` の 4 段」を絶対の高さで当てはめて g を出し、
  ほかの型にもそのまま使う。周波数の位置をずらす必要は無かった（ずらすと悪くなる）
* 部品は 1 次の低域通過（LP1）と、Chamberlin の状態変数フィルター（SVF。`hp = x − lp' − q bp'、bp = g hp + bp'、lp = g bp + lp'`）

  | 型 | 形 | 誤差（dB の RMS。目盛り 60-100 / 100-140 / 140-180 / 180-210 / 210-226） |
  |---|---|---|
  | LPF24D | SVF 低域（q=2）× 2 段 | 0.14 / 0.13 / 0.30 / 0.60 / 3.05 |
  | LPF24A | SVF 低域（q=1.414）× 2 段 | 0.20 / 0.18 / 0.27 / 0.53 / 1.48 |
  | LPF18 | SVF 低域（q=2）× LP1 | 0.10 / 0.10 / 0.27 / 0.47 / 1.61 |
  | LPF18s | LP1 × LP1（g × 5.66） | 0.92 / 0.77 / 0.83 / 0.19 / 0.14 |
  | LPF12・DualLPF・LPF12+BPF6 | SVF 低域（q=2） | 0.06〜0.21 / 0.07〜0.16 / 0.19〜0.20 / 0.29〜0.42 / 1.3〜1.6 |
  | LPF6 | LP1 | 0.17 / 0.16 / 0.15 / 0.20 / 0.19 |
  | HPF24D | SVF 高域（q=2）× 2 段 | 0.27 / 0.16 / 0.30 / 0.51 / 1.93 |
  | HPF12 | SVF 高域（q=2） | 0.19 / 0.20 / 0.19 / 0.29 / 1.32 |
  | BPF12D | SVF 帯域（q=2）× 2 段 | 0.21 / 0.24 / 0.35 / 0.58 / 2.63 |
  | BPFw | SVF 帯域（q=1）× 2 段 | 0.29 / 0.29 / 0.46 / 0.86 / 1.00 |
  | BPF6 | SVF 帯域（q=2） | 0.09 / 0.13 / 0.20 / 0.31 / 1.49 |
  | BEF12 | SVF 帯域阻止（q=2）× 2 段 | 0.38 / 0.37 / 1.09 / 3.02 / 4.42 |
  | BEF6・DualBEF | SVF 帯域阻止（q=2） | 0.49 / 0.75 / 1.70 / 3.0 / 3.8〜4.2 |
  | DualHPF | 素通し + SVF 高域（q=2） | 0.02 / 0.02 / 0.06 / 0.25 / 1.16 |
  | DualBPF | SVF 帯域（q=2）+ 0.707 × SVF 帯域（g × 2^−7.5、q=1.414） | 0.10 / 0.25 / 0.37 / 0.49 / 1.45 |

* q=2 は「等しい 2 つの実の極」（アナログで言えば Q=0.5）、q=1.414 はバターワース。LPF24D と LPF24A の違いはこれだけ。
  LPF12+BPF6 と DualLPF は、レゾナンス 0 では LPF12 と同じ形（違いはレゾナンスで出るはず）
* 通る所の高さのずれは、どの型も 0.2dB 以内（LPF12 +0.20、LPF12+BPF6 +0.19、LPF6 +0.15 ほか）
* **いちばん上（目盛り 210 から上）は 1〜4dB ずれる。** q=2 の Chamberlin の SVF は g が 0.83 を超えると不安定になるので、骨組みでは g を 0.82 で止めている。
  実機は安定しているので、いちばん上のつくりは少し違うはず。帯域阻止の型と LPF18s は中ほどでもずれが大きい（形の見立てが足りない）
* **前に「当てにならない」とした範囲について。** 目盛り 60 より下が 37〜45Hz で平らになったのは、通る所の基準を 25〜40Hz で取っていたため（カットオフがそれより低いと基準が下がる）。
  g は基準を使わない絶対の高さで当てはめるので、目盛り 0 まで出せた（0 で g = 0.00206、約 14.5Hz。25Hz より下は測れないので誤差 0.4〜0.9dB）。
  高域通過の型の目盛り 190 より上も同じ理由（基準の 15〜18kHz が動く）で、形の当てはめでは低域通過の型と同じ程度に合う
* 曲線の取り出しは `mr_filterfit.py curves`（全部の録音で約 1 分）、型ごとの誤差は `mr_filterfit.py check`
* レゾナンス・キーフォロー・HPF は後ろの節。まだ入れていないのは、型ごとの g の上限の扱いと、レゾナンスの飽和

### レゾナンス（2026-10-19。`tools/motif/mr_reso.py`、録音は `capture/reso/`）

18 型 × カットオフ 96・128・160・192 × レゾナンス 0〜127（8 刻み + 127）を、`mr_cutoff.py` と同じ条件（キーフォロー 0、基準は THRU）で録った（1,224 本）。
前の形の模型の SVF の q だけを、レゾナンスごとに当てはめた（g は目盛りの表のまま）。

* **多くの型で、q は「レゾナンス 16 ごとに半分」**: `q = 2 × 2^(−reso/16)`（レゾナンス 0 で q = 2）。目盛りによらない。
  当てはまる型: LPF24D・LPF18・LPF12・HPF24D・HPF12・BPF12D・BPF6・DualLPF・DualHPF・DualBPF・LPF12+BPF6
* **注意（2026-10-19 に分かった）: この録音では、雛形の音色のレゾナンスのベロシティ感度（0x06 = 99、+35）を直していなかった。**
  ベロシティ 100 で弾いたので、実際のレゾナンスは書いた値より 35 × 27/128 = 7.4 低い。書いた値で見ると `q = 2.74 × 2^(−reso/16)`（上限 2）に見えたのはこのため。
  感度を 0 にした録音（`mr_fscale.py`）では、レゾナンス 32 で q = 0.511（式は 0.5）。下に書くレゾナンスの値は、すべて書いた値（7.4 を引く前）
* 誤差（目盛り 96〜160、飽和の手前まで）は 0.1〜0.5dB。目盛り 192 では 0.3〜1dB
* **飽和**: レゾナンスが高いと実機は発振して飽和する。f0 の山は +40dB ほどで止まり、ほかの帯域が −17〜−21dB まで押し下げられ、高域に倍音が出る（4kHz から上で +5dB）。
  線形の模型では表せない。始まる所は段の数で決まり、4 段の型（LPF24D・HPF24D・BPF12D）はレゾナンス 40〜48、2 段の型は 80、LPF18 は 88 から上
* **外れる型**（測った q の表を対数で補間して使う）:
  * LPF24A: q の下がり方が遅い（レゾナンス 64 で 0.49、104 で 0.34）。f0 の山の頂上は模型が 2〜3dB 低い（レゾナンス 64 で模型 12.2dB、実機 15.0dB）。
    2 段めだけ下げる形や、全体を帰還させる形はもっと悪かった
  * BPFw: 逆に q が上がって帯域が広がる（レゾナンス 0 で 1.0、64 で 2.6、127 で 12.6）。山の高さは保たれるので、模型は q で高さを戻す。レゾナンスが高い所は 2〜3dB ずれる
  * 帯域阻止（BEF12・BEF6・DualBEF）: 下がり方が少し遅い。形そのものの誤差（1〜1.5dB）が残る
* **LPF6 はレゾナンスが効かない**（どのレゾナンスでも同じ形）
* **LPF18s は f0 に山ができず、f0 の約 7 倍の所が持ち上がる**（目盛り 128 で 3.2kHz が −19 → −11dB、その上の落ち方が急になる）。
  2 つめの段（f0 の 5.66 倍）が共鳴する形と見えるが、ナイキストに近すぎて今の部品では合わない。**模型ではまだ効かせていない**
* 骨組みでは `swp50_filter::type_q(型, レゾナンス)` と `element_filter::set(型, 目盛り, レゾナンス)`。Chamberlin の SVF が不安定にならないよう、q には上限を付けた（`stable_q`）

### キーフォローと HPF（2026-10-19。`tools/motif/mr_kf.py`、録音は `capture/kf/`）

**カットオフのキーフォロー（0x22）**: 型 BEF12・目盛り 128 で、キーフォロー 9 段階 × 鍵 36・48・60・72・84 を録り、谷の位置（f0）を出した。鍵ごとの素通しで割っている。

* **中心の鍵は 60（C3）**。どの値でも鍵 60 の f0 は 458〜459Hz
* 値 0〜127 が −200%〜+200%（64 が 0%）。測った傾きは値 0・16・32・48・64・80・96・112 で −202・−150・−100・−49・0・+50・+100・+153%
* **キーフォローは目盛りの側に足される**。100% のとき 1 半音で 2.13 目盛り（1 オクターブで 25.6 = 目盛りのくり返し 1 つ）。
  そのため、鍵 1 オクターブで何セント動くかは一定ではない（目盛り 128・50% で、鍵 +12 が +680 セント、−12 が −528 セント、±24 は ±1,200）。
  ±6 半音ぶん動かす所だけ、測った値と 1.8 目盛りほどずれる
* 値 127・鍵 84 は、f0 が 7,330Hz になるはずが 59Hz になった（同じ量だけ反対に動かす値 0・鍵 36 は 7,369Hz で頭打ち）。HPF のキーフォローでも、値 127・鍵 84 だけ崩れる。理由は分からない

**HPF（0x07、0〜255）**:

* **HPF が効くのは、型が LPF12 と LPF6 のときだけ。** ほかの型では、値は編集バッファに入る（読み戻すと `01 48` = 200）が音は変わらない。THRU でも効かない。
  チップのフィルターの段が余るのが、この 2 つの型だけなのだろう（**見立て**）
* 型 LPF6・カットオフ 255 で HPF を 0〜254 の 2 刻みで録り、同じ設定で HPF 0 の音と比べた。**形は SVF の高域通過で q ≈ 1.05、目盛り → g はカットオフと同じ表**
  （g を表の値に固定して、目盛り 16〜208 で誤差 0.25〜0.5dB。q = 1.0 と 1.1 がほぼ同じ）。実機は f0 の少し上に +1.4dB の小さな山がある
* 目盛り 0 は効かない（「切」）
* **HPF のキーフォロー（0x2F）もカットオフと同じ決まり**: 中心の鍵 60、100% で 1 半音 2.11〜2.19 目盛り

骨組み: `element_filter::set(型, 目盛り, レゾナンス, キーフォロー, 鍵, HPF, HPF のキーフォロー)`、`cutoff_with_keyfollow`、`g_at`（小数の目盛りの g）。

**録り方の落とし穴**: 最初は型を THRU にして HPF を録ったが、何も効いていなかった（`capture/kf_hpf_thru_bad/`）。LPF24D でも同じ（`capture/kf_hpf_lpf24d_bad/`）。

### Distance・Filter Gain・カットオフのベロシティ感度（2026-10-19。`tools/motif/mr_fparams.py`、録音は `capture/fparams/`）

雛形の音色の値は、読み戻すと Distance 0、Filter Gain 250、ベロシティ感度 64（0）。前の測定はこの状態のもの。
レゾナンスの欄の Data List の名前は「Resonance/Width/Band」で、BPFw では幅として働く（レゾナンスを上げると帯域が広がったのはこのため）。

**Distance（0x0A、0〜255。Dual 系の型だけ）**: Dual 系の 4 型・目盛り 128 で、0〜255 を 16 刻みで録った。

* **Dual 系の型は 2 つのフィルターを持ち、2 つめの目盛り = 1 つめ + 1.6 ×（Distance − 128）。** DualBEF の 2 つめの谷で測ると、きれいに出た点はどれも 1.598〜1.606。
  Distance 16 で 25.6 目盛り（くり返し 1 つ = 1 オクターブ）、128 で 2 つが重なる
* 組み立て: DualLPF・DualHPF・DualBPF は SVF（q=2）2 つの**和**（重なると +6dB）、DualBEF は 2 つの**直列**（谷が 2 つ。重なると −79dB）。
  誤差は Distance 0〜176 で DualLPF 0.1〜0.4、DualHPF 0.0〜0.8、DualBPF（48〜176）0.1〜0.2、DualBEF 0.5〜1.9dB。192 から上は 2 つめが上限に貼りつき 1.3〜3.3dB ずれる
* 前に DualHPF を「素通し + 高域通過」、DualBPF を「帯域通過 + 0.707 × ずっと低い帯域通過」と見たのは、Distance 0 で 2 つめがずっと低い所（目盛り −77）にあったため。
  骨組みでは目盛り 0 より下の g を 25.6 目盛りで 1 オクターブとして外へ延ばす

**Filter Gain（0x0C、0〜255）**: 型 LPF6・目盛り 255 で 0〜255 を 32 刻みで録った。**dB でまっすぐ、1 あたり 0.375dB**（チップの減衰の単位と同じ）。
32 以下は無音。255 を 0dB とすると、64 で −71.7dB（式 −71.6）。雛形の 250 は −1.9dB

**カットオフのベロシティ感度（0x03、−64〜+63、64 が 0）**: 型 BEF12・目盛り 128 で、感度 9 段階 × ベロシティ 1・32・64・100・127 を録り、谷の位置を目盛りに直した。

* **目盛りの動き = 0.0285 × |感度 − 64| ×（v − 115）**。v は感度が正ならベロシティそのもの、負なら 128 − ベロシティ（裏返し）。
  測った 30 点との差は RMS 1 目盛り、最大 1.7 目盛り
* 動かないのはベロシティ 115（感度が負なら 13）で、64 ではない。感度を最大にすると、ベロシティ 1〜127 の間で 226 目盛り（約 9 オクターブ）動く

骨組み: `element_filter::set(…, distance, vel_sens, velocity)`、`velocity_steps`、`filter_gain_db`。

### カットオフのスケーリングとレゾナンスのベロシティ感度（2026-10-19。`tools/motif/mr_fscale.py`、録音は `capture/fscale/`）

雛形の音色のスケーリングは、ブレークポイント 27・48・72・84、ずらしは全部 0。**カットオフのキーフォローは 76（+37.5%）**、レゾナンスのベロシティ感度は 99（+35）だった。
波形の下録り（`mr_sweep.py`）はこの雛形でカットオフ 255 にして録っているので、低い鍵ではキーフォローで目盛りが下がり（鍵 0 で約 207、4kHz あたり）、弱い低域通過が掛かっている。
隣の鍵どうしの差は 1 目盛り弱なので、境目の見立てへの影響は小さいと見ている。

**スケーリング（ブレークポイント 0x23〜0x26、ずらし 0x27〜0x2D、128 が 0）**: 型 BEF12・目盛り 128 で、ブレークポイントを 36・48・72・84、
ずらしを A =（+40、−40、+40、−40）、B =（全部 +64）にして、鍵 24〜96 を 3 刻みで録った。

* **ずらしを全部 +64 にすると、どの鍵でもちょうど +51.2 目盛り**（ずらし 1 = 0.8 目盛り。32 で 25.6 目盛り = 1 オクターブ）
* **ブレークポイントの間はまっすぐつなぐ。いちばん外のブレークポイントより外側は、その値のまま**（A の鍵 24〜36 は全部 +30.6、鍵 84〜96 は全部 −33）
* ずらし ±40（1.25 オクターブ）のときは +30.6 / −33.4 目盛り（0.8 倍なら ±32）。セントで見ても 1 単位 39.4 / 36.3 セントとそろわない。
  オクターブの整数倍の量だけが正確で、キーフォローのときと同じ性質。チップの中の目盛りの表し方がもう一段違うのだろう

**レゾナンスのベロシティ感度（0x06、64 が 0）**: 型 BPF6・目盛り 128・レゾナンス 32 で、感度 0・32・64・96・127 × ベロシティ 1・32・64・100・127 を録り、q を当てはめた。

* 感度が正なら**ベロシティ 127**、負なら**ベロシティ 1** のとき、レゾナンスは書いた値のまま。そこから離れるほど `|感度 − 64| × 離れた量 / 128` だけ下がる。
  書いた値より上がることはなく、0 より下にもならない（感度 +32・ベロシティ 64 で 32 → 15.6、感度 −64 だとベロシティ 64 から上で 0）

骨組み: `filter_params` と `element_filter::set(パラメーター, 鍵, ベロシティ)`、`scaling_steps`、`resonance_with_velocity`。q の式と外れる型の q の表は、7.4 を直した値にした。

### フィルター EG（FEG）（2026-10-20。`tools/motif/mr_feg.py`、録音は `capture/feg/`）

型 BEF12・目盛り 128 で、谷の位置を 4,096 点・512 点おきの区切りで追った。FEG の時間と高さのベロシティ感度、時間のキーフォローは 0 にした
（雛形の音色では +63・+63・+16。深さは 64 = 0 なので、前の測定には FEG は効いていない）。

**深さと高さ**: 5 つの高さを全部 L、時間を全部 0 にして、L（+32・+64・+127・−64）× 深さ（0・32・64・96・127）で谷が止まった位置を見た。

* **動き（オクターブ）= 高さ ×（深さ − 64）/ 1024。** 高さ +32・深さ +32 で +1,199 セント、高さ +64・深さ +32 と高さ +32・深さ +63 で +2,412 セント。
  深さを +64 とみなせば高さ 1 = 75 セントで、Data List の「−128〜+127（−9600〜+9600 セント）」と合う
* 上は 7,389Hz で頭打ち
* **目盛りが 0 より下に出ると、0 で折り返す。** 高さ +127・深さ 0（−8 オクターブ = −202 目盛り）で、谷は 107Hz（目盛り 128 − 202 = −74 の絶対値 74 の周波数）に来た

**時間**: アタック（高さ −64 → +64）とディケイ 1（+64 → −64）の時間を変えた（深さ +63）。

| 時間の値 | 48 | 64 | 80 | 96 以上 |
|---|---|---|---|---|
| アタック 10% / 50% / 90% の時刻（秒） | 0.046 / 0.070 / 0.128 | 0.070 / 0.395 / 0.708 | 0.128 / 1.591 / 2.821 | 4 秒で終わらない |
| ディケイ 1 | 0.046 / 0.093 / 0.151 | 0.093 / 0.406 / 0.720 | 0.372 / 1.579 / 2.914 | 同 |

* **高さの単位でまっすぐ動く**（50% / 90% の時刻 = 0.55〜0.56、まっすぐなら 0.556）。高さはセントなので、カットオフはオクターブでまっすぐ動く
* **段の長さは、音量の EG の下がる側（表 8C0DDC08）と同じ。** 骨組みの式で `swp50_eg::time_down(127 − 時間の値)`: 64 で 34,950 サンプル（0.79 秒）、80 で 3.17 秒。
  上がるとき（アタック）も下がる側の表を使う（音量の EG のアタックの表なら 64 で約 0.07 秒）。値 48 は式で 0.198 秒、測定は約 0.15〜0.17 秒（区切りの粗さの範囲）
* かかる時間は高さの差によらない（音量の EG と同じ選び方）とみている。アタックとディケイで差は 128 で同じなので、録音では確かめていない

  （Tunnel・Canyon・R3 Plate は外れる）。高い帯は短く、その割合は残響時間が長いほど強い（8kHz / 1kHz が 1.3 秒で 0.9、28 秒で 0.47）

* **送りは CC91 で決まり、音量に比例**: CC91 = 96・64・32 で −2.5・−6.1・−12.1dB。音色の共通部分の Reverb Send（40 00 0B）は、CC91 を送ると
  上書きされて効かない（音色を選んだときの初めの送りとして入るとみている）

**芯で掛ける**（`tools/motif/mr_fx_apply.py`。今は WAV の後処理）: 型の既定で測った応答を、Reverb Time の表 4 の秒に合わせて帯ごとに伸び縮みさせ、
Return / 96 × 送り / 127 を掛けて、左右の平均を畳み込む。リバーブを残して録ったプリセット（TouchClavi・Flutey・Harpsicord・Accordion・Mute）と
比べると、離したあとのリバーブの大きさ（元の音の大きさから）は実機と 2dB 以内（Flutey −33 / −33、Accordion −18 / −20、TouchClavi −29 / −31dB）で、
減り方の形もそろう。確かめていないこと: Reverb Time 以外のパラメーター（Initial Delay・HPF・LPF・High Damp など）、表 25〜27 の型の伸び縮み、
Reverb Pan、送りの量の曲線の小さい所

### ボイスのコーラス（2026-10-21。`mr_fx.py --train` で録り `mr_fx_chorus.py` で読んだ。録音は `capture/fxc/`）

コーラスは遅れが LFO で動くので、1 本の応答では表せない。短いノイズの音を 0.1 秒おきに 6 秒鳴らし続け（60 回）、dry の 1 発を型に wet 全体を逆畳み込みして、
0.1 秒ごとの応答を並べる。各回の 5〜60ms で一番大きい線の遅れ（1 サンプル未満まで）と高さを左右ごとに読む
（初めは鳴らし終わったあとの回も読んでいて、雑音を拾っていた）。型は Chorus 1（05 00）、既定は LFO Speed 6・LFO Depth 54・Feedback 77・Delay Offset 106・Return 96。

* **線は左右に 1 本ずつ**（26.9ms でドライの線の 1.40 倍。ほかは ±0.1 前後の読みの雑音。53.6ms に 0.15 の線があり、フィードバックかもしれない）
* **遅れ = Delay Offset（表 2）から上へ、三角波で動く**: 一番短い遅れは深さによらず約 17.5ms（表 2 の 106 = 17.1ms）。
  振れ幅は LFO Depth に比例して 0.176ms × 深さ（27・54・108 で 4.4・8.7・17ms）。速さは表 1（6 → 0.25Hz、20 → 0.833Hz）。**左右は逆の向き**
* **高さ**: 線の山から読むと 1.3〜1.4（速く動くと 0.06 秒の音の中でぼやけて低く読める）。コーラスを足したときのエネルギーの増え方から読むと
  **2.06**（深さ・速さを変えた 4 本で 2.05〜2.07）。芯ではエネルギーの方を使う
* Feedback（64・77・100）を変えても主な線の高さはほとんど変わらず、まだ読めていない
* 表 1（LFO の速さ）・表 2（遅れのずらし）は Data List の Effect Data Assign Table から読み、`mr_fx_apply.py` に入れた

**芯で掛ける**（`mr_fx_apply.apply_chorus`。Chorus 1〜5・Celeste 1〜4 の型）: 上の形で、高さ 2.06 × Return / 96 × 送り / 127。
コーラスの送りの大きいプリセット 5 つ（Superstrgs・SmoothBlue・Shine on・Clean Gt・ChurchOrgn）を、リバーブとコーラスを残して録って比べた
（`mr_preset_compare.py --fx`）。エフェクトで足された音量は実機 +0.6〜+2.6dB・芯 −0.1〜+2.2dB（高さ 1.4 のときは芯 −0.1〜+1.7dB）、
左右の差の割合（広がり）は実機と芯で近い。持続音ではコーラスの線と元の音が干渉し、足し算の結果が位相で変わるので、±1〜2dB はこの方式の幅とみている。
Chorus 1 以外の型は同じ形と仮定した（確かめていない）。インサーションはまだ

### インサーションの 3 Band EQ（2026-10-21。`mr_fx.py --block insa` で録り `mr_fx_eq.py` で読んだ。録音は `capture/fxi/`）

インサーションの型（Effect Type List の 2 ページ目。2 段組みが崩れているので、名前の並びと番号の並びを分けて読んで突き合わせた）:
Distortion 09 00、Comp+Dist 09 01、V-Distortion 09 10、Overdrive 09 20、Amp Simulator 09 30・2 09 31、Dist+Delay 09 40、Odrv+Delay 09 41、
Compressor 0A 00、Noise Gate 0A 20、Cmp+Dist+Dly 0A 40、Cmp+Odrv+Dly 0A 41、Multi Band Comp 1・2 0A 50・51、Pitch Change 1・2 0B 00・01、
Auto Wah 系 0C 00〜0C 41、Lo-Fi 系 0D 00〜50、Tech 系 0E 00〜50、3 Band EQ 0F 00、2 Band EQ 0F 01、Enhancer 0F 10、Voice Cancel 0F 20、Ambience 0F 30、
Talking Mod 0F 40、Beat Change 0F 50、Ring Mod 0F 70、Dynamic Ring Mod 0F 71、Dynamic Filter 0F 78（ほかにリバーブ・ディレイ・コーラス系の型も入る）。
プリセットのインサーション A で多いのは 3 Band EQ（370）・型なし（147）・2 Band EQ（41）・Compressor（37）・Amp Simulator（24）・Enhancer（22）。

**測り方**: エレメントのインサーションのスイッチ（41 ee 16）を 0 にした録音（dry）と 1（インサーション A）にした録音（wet）を比べる。
**最初は 1kHz に −4dB の谷が、型なしでも出た**。雛形の音色（Full Grand）はつなぎ方が A → B で、B の EQ を通っていた。
つなぎ方（40 00 40）を 0（並列）にすると、型なし・平らな 3 Band EQ とも ±0.1dB 以内で平らになった。

3 Band EQ のパラメーター: 01 低の利き・03 中の利き・05 高の利き（52〜76 で −12〜+12dB）、02 中の周波数・06 低の周波数・07 高の周波数（表 3）、04 中の幅（Q 0.1〜12.0）。
21 本の格子（帯ごとに周波数・利き・幅を変えた）から:
* **利きは 1 目盛り 1dB**（中の 70 で +6.0、76・52 で ±12.0）
* **低・高は 1 次の棚**（6dB/オクターブ）。双一次変換の 1 次の棚に当てはめると、**角は 低 = 表 3 × √2、高 = 表 3 / √2** で 0.2〜0.5dB
  （高の 16kHz だけ 2.2dB）。2 次の RBJ の棚（S = 0.5）では 1.9dB ずれる
* **中は、上げるときは分子だけ・下げるときは分母だけに利きを入れる山で、Q = 幅 / 10**（RBJ の山の分母と分子の両方に √A を入れる形ではない）。
  8 本中 7 本が 0.07〜0.16dB（幅 120 は山が細すぎて 1/3 オクターブで拾いきれず 1.45dB）
* 表 3 は 1/6 オクターブの並び（24 = 315Hz、34 = 1.0kHz、58 = 16kHz）

**芯で掛ける**（`mr_fx_apply.apply_insertion`）: 3 Band EQ を使い、全部のエレメントがインサーション A を通る音色 5 つ（PizzEns・BlownBone・QuietBrass・Kemence・Aah Choir）を
インサーションを残して録って比べた（`mr_preset_compare.py --ins`）。スペクトルの差は 0.1〜0.8dB（中を +12dB 上げている Kemence も 0.1〜0.3dB）。
QuietBrass だけ 2.8〜4.9dB だが、インサーションなしでも 2.8〜4.4dB 違うので、EQ ではなく音色の側の差。
まだのもの: 2 Band EQ・Compressor・Amp Simulator・Enhancer など、エレメントごとに違うインサーションを通る音色（芯はエレメントを足してから掛けている）

### Dry Level の測り直し（2026-10-18。録音は `capture/dry/`）

### 下録り全部（1〜1859）の境目の見立て（2026-10-18。`tools/motif/mr_zones.py`、結果は `capture/zones_all.csv`）

最初に 1,859 本を前のままの道具で回すと、区間の合計が 51,659 になった。Firm の鍵の表の記録は 14,106 個なので、明らかに多すぎる。
ハイハット・シェイカーのような雑音の波形で、同じサンプルなのに「境目」と出ていた。原因は 4 つあった。

* **隣の鍵との音程の比が 2^(1/12) ちょうどではない。** 比を少しずつ変えて重ねると、いちばん合うのは **2^(85/1024) か 2^(86/1024)**（半音 = 85.33 目盛りを鍵ごとに丸めた値。
  ハイハット 1589 の鍵 50〜75 で +0.05〜0.08% と −0.02〜−0.03%）。音程のある音ではこの差は効かないが、雑音は 6,000 サンプルで数サンプルずれて重ならなくなる。
  チップの音程が 1 オクターブ = 1024 目盛りで鍵ごとに丸められる、という静的な読み（r = 0x0A）と合う。道具は 2 つの比の良いほうを使うようにした
* **前の音の余韻が残っている鍵では、出だしの位置が当てにならない**（トライアングルなど、余韻が 0.12 秒の隙間より長い音）。そういう鍵だけ、ずれを ±300 サンプルまで探す。
  音程のある音でいつも広く探すと、隣の区間のサンプルの似た周期に乗ってしまう（ピアノの 3 鍵ごとの境目が消えた）ので、そうしない
* **元の鍵より上では、高域が折り返されて（エイリアス）鍵ごとに違う音になる。** 読む速さが r（1〜2）なら、折り返しは 22,050 × (2 − r) Hz より下へは落ちないので、
  音程の無い音だけ、8k・4k・2k・1kHz より下の帯域でも比べる（印は `l`）。ハイハット 1589 は 53 区間 → 1 区間になった。
  音程のある音に使うと、ピアノの隣のサンプルどうしが低い帯域で重なって境目が消えるので使わない
* **高い鍵の音程の折り返し**（次の節）。その鍵から上は境目に数えない（印は `w`）

直したあとの合計は **16,517 区間**（ドラム 4,202 → 3,342、効果音 777 → 644 など）。
記録の 14,106 個とは直接は比べられない（ステレオの波形と L・R の波形、「+」「−」の変種は、同じ記録を分け合っているかもしれない）。
残っている当てにならない所:

* `?`（見分けられない）: 雑音の波形で、波形は重ならないが音量の形は重なる所。560 本・12,935 鍵。読む速さが 2 を超える所（低い帯域も使えない）がほとんど
* `~`: 音程のある音で、相関が 0.9〜0.95。同じサンプルと見て境目には数えないが、よく似た隣のサンプルとの境目かもしれない（690 本・3,090 か所）。
  ピアノ 9 の鍵 77/78 は本物の境目で 0.925、ピアノ 7 の鍵 29〜31 は同じサンプルのはずの所で 0.91。線では分けられない
* トライアングルのような、音程はあるが倍音が整っていない音の高い鍵（937 の鍵 66 から上など）

**印が S・|・= だけの波形の境目は当てになる**。ピアノ 1〜35 は 33 区間前後、ドラムは中央値 1 区間。

ほかに分かったこと:

* **Aco FX2（274）は、鍵 n と n+12 がまったく同じ音**で、隣の鍵とは別の音。音程を追わない 12 個の効果音が 1 オクターブごとにくり返す並び（`octave` 列に o）。
  区間の数え方では 118 になるが、サンプルは 12 個だろう
* 前に 252 本だけ見立てた `zones2.csv` とは、前のままの道具で 252 本とも同じ境目になった（録り直しの雑音の影響は無い）

### 高い鍵の音程の折り返しと頭打ち（2026-10-18。`tools/motif/mr_wrap.py`、録音は `capture/wrap/`）

**まとめ: 読む速さが 3 倍（サンプル 3 つ / 出力 1 つ）に届くと、1 オクターブ下へ戻る。** 何オクターブ上でもくり返すので、実際の読む速さはいつも 1.5〜3 倍の間に入る。
別に、「鍵 + コースチューン」は 127 で頭打ちになる。骨組みには `swp50_device::fold_pitch()` として入れた

下録りの 443 本で、ある鍵から上が **1 オクターブ下へ戻り、そこからまた上がる**（鍵 n と n+12 がそのまま重なる）。何オクターブ上でも同じことがくり返す。
Organ Full（125）は鍵 120 の 8,371Hz の次の 121 で 4,696Hz（鍵 110 の高さ）へ戻り、境目の一覧の最上段（125 の 121、Wurli 69 の 120）はこれが作った偽物だった。

鍵の区間（わざとの折り返し）なのか音程の天井なのかを見分けるため、エレメントのコースチューンを −12・0・+12 にして鍵 40〜127 を録った。

| 波形 | 折り返しの始まり（−12 / 0 / +12） | +12 の頭打ち |
|---|---|---|
| 125 Full（オルガン） | なし（132 のはず）/ 121 / 109 | 鍵 116 から 6,270Hz のまま |
| 69 Wurli | なし（131 のはず）/ 120 / 108 | 鍵 116 から 6,259Hz のまま |
| 972 BdSnap1-2 | 97 / 85 / 73 | 鍵 116 から同じ音 |
| 1589 HHOpRkL | 90 / 78 / 66 | 鍵 116 から同じ音 |

* **折り返しの始まりは、コースチューンと同じだけちょうど 12 鍵動く。** 鍵の区間ではなく、**音程の天井**で決まる。オクターブの部分が頭打ちになり、
  オクターブの中の部分（1024 目盛りの下 10bit にあたる所）だけが回り続ける形
* 天井の位置は波形ごとに違う（オルガン・EP は 120 前後、ドラムは 78〜87 に固まる）ので、サンプルの元の音程からの距離で決まっている。
  初めは「元の鍵 + 24 半音」と見たが、次の測り方で**読む速さ 3 倍**と分かった
* **元の鍵（読む速さ = 1 の鍵）は、低い鍵のスペクトルから測れる**（`tools/motif/mr_root.py`）。 元の鍵より下では、チップの補間の像が「読む速さ × 44,100Hz」おきにくり返す
  （ハイハット 1589 の鍵 18 で 4,242Hz おき）。この間隔から逆算した元の鍵は、鍵 0〜38 のどれで測っても 58.54（36 鍵の値が ±0.01 で一致）。
  1 区間で折り返しのある波形 338 本を測り、値がそろった 289 本で、**折り返す直前の鍵の読む速さは最大 2.9967 倍、折り返した鍵は最小 3.0176 倍**。
  外れは 1 本だけ（473 SitarWv3。前から形の違う波形）。1024 目盛りで言うと、境目は 1622〜1631 の間（log2(3) × 1024 = 1623）。骨組みでは「3 倍以上」= 1624 と置いた
* 元の鍵の端数は 0（79 本）、0.52〜0.56（110 本）、0.15（65 本）にかたまる。0.55 は 32kHz、0.53 は 48kHz（か 24kHz）で録ったサンプルを 44.1kHz で鳴らすぶんのずれと合う
  （1589 は鍵 5・17・29 の間隔がちょうど 2,000・4,000・8,000Hz で、32kHz のサンプル）。0.15 は何のずれか分からない
* SWP30 の作り（MAME）は 4.10 の符号つきで 256 倍まで読めるので、ここは SWP50 で違う所。Firm は音程を ±9600 セントで切るだけなので、3 倍の天井はチップの側だろう（**見立て**）
* **+12 では鍵 115〜127 がすべて同じ音**（4 本ともずれを広く探した相関 1.00。オルガンは 6,270Hz = 音の番号 115、つまり 127 を折り返した高さ）。オルガンと Wurli で天井の位置が違うのに、頭打ちはどちらも鍵 116 から。
  **「鍵 + コースチューン」が 127 を超えると 127 で止まる**（音の番号での頭打ち。Firm の側だろう）
* 音程のある波形でも、ふつうの音色では起きにくい（鍵 120 前後で、しかも上の区間ほど元の鍵が高い）。ドラムや効果音を高い鍵で鳴らすと、音程が上がらずくり返す
* 雑音の波形は出だしの位置が数十サンプルぶれる（ハイハットのコースチューン 0 を 2 回録ると、そのままでは鍵の半分ほどが重ならず、ずれを ±300 まで探すと全部 1.00）。
  比べるときはずれを広く探すこと

## 波形の下録りの試し（2026-10-13）

**同じサンプルなら相関が 0.98 以上、違うサンプルなら 0.7 以下**にはっきり分かれた。境目は 32 か所（ほぼ 3 鍵ごと）。

* この方法で、鍵ごとのサンプルの割り当てが音から取れる
* 全部の波形を回す道具が `tools/motif/mr_sweep.py`（1 波形 = 128 鍵 × 0.52 秒 ≒ 67 秒、24bit の WAV で約 18MB。1,859 本で約 35 時間・33GB の見積もり）。
  もう録ったものは飛ばすので、何晩かに分けて回せる。結果は `capture/wave/` に、境目の見立ては `zones.csv` に溜まる

## やってはいけないこと

* **検査モードの T12（MIDI では `A0 0C 00`）は Factory Set。ユーザーのデータが全部消える。** 検査モードには、先に控えを取るまで入らない
* 取扱説明書と Data List に載っていない SysEx は送らない
* 更新の受け付け状態（[EXIT]・[PAGE>]・[MUTE/SEL/ENTER] を押しながら電源）には入らない

## 0. 用意するもの

| | 状態 |
|---|---|
| Data List（PDF） | 手に入った（2026-10-13）。`pdftotext -layout` で読めるが、2 段組が崩れる |
| MIDI の線 | RACK ES の MIDI IN / OUT ↔ パソコンの MIDI の口（DIN）。**どの口を使うかは未確認**（RACK ES の USB-MIDI のドライバは古く、今の Windows で動くか分からない） |
| デジタルの音の線 | RACK ES の OPTICAL OUT → Babyface の光入力。44.1kHz・24bit |
| 送る道具 | `build/midisend.exe`（MIDI ファイルを流す）、`build/rec.exe --send`（録りながら流す） |
| 受ける道具 | SysEx をファイルに落とせるもの（MIDI-OX など）。`tools/dump/recv_dump.py` は MU2000 専用なので、そのままでは使えない |
| 確かめる道具 | `tools/motif/mr_bulk.py check`（チェックサムと長さ）、`mr_wavenames.py`（波形の名前の一覧） |

Babyface の設定は MU2000 の録音と同じ（44,100Hz。クロックは RACK ES の光入力に合わせる）。録音は `rec.exe --float` で。

## 1. 控えを取る（最初に必ず）

パネルから全部のユーザーのデータをバルクダンプして、ファイルに落とす。こちらからは何も送らない。

1. 受ける道具を、SysEx を全部ファイルへ落とす状態にしておく
2. RACK ES の UTILITY からバルクダンプを実行する（操作は取扱説明書のとおり）
3. `python tools/motif/mr_bulk.py check 控え.syx` で、全部のメッセージが OK になることを確かめる
4. **もう 1 回取って、2 つのファイルが同じ中身かを比べる**（途中で欠けていないかの確認）

これがそのまま、何かあったときに戻すための控えになる。戻すときは同じファイルを実機へ流す。

## 2. プリセットの音色を取る

Data List が来てから。手順は 2 通りあり、Data List を見てから選ぶ。

* **プリセットを番地で直接要求できる場合**: 音色ごとにダンプ要求（`F0 43 2n 7F 00 ah am al F7`）を送り、返ってきたバルクを保存する
* **「今の音色」しか要求できない場合**: バンクセレクトとプログラムチェンジで音色を選び、「今の音色」をダンプ要求する。これを全音色ぶん回す

どちらも 1 音色ずつ「送る → 返事を待つ → チェックサムを確かめる → 保存」。返事が無い・チェックサムが合わないときは、同じ音色をやり直す。
要求のバイト列は `mr_bulk.py request ah am al` で作れる。

取れたら、音色ごとに次を表にする（Data List のパラメーターの並びで読む）。

| 取り出すもの | 使い道 |
|---|---|
| エレメントごとの波形番号、鍵の範囲、ベロシティの範囲 | 録音の計画（どの波形を、どの鍵で録るか） |
| エレメントの音量、EG の時間と高さ、フィルター、LFO | 静的な読みで出した換算の式の答え合わせ |
| リバーブ・コーラスへの送り | 「送りの 4 本」のどれが何かの決め手 |

## 3. 基準の録音（短い。静的な読みの答え合わせ）

デジタル出力で録る。1 本あたり数秒から十数秒。**どの録音も 2 回ずつ録って、同じになるかを見る**（同じなら出力は決まった値で、あとの比べが楽になる）。

雛形の音色を 1 つ作っておく: エレメント 1 つ、フィルターは通すだけ、EG は平ら、LFO・エフェクト・EQ は切る、パンは中央。
波形は 1 周期が分かりやすいもの（波形の名前の表の `Sine`）。

| 録るもの | 確かめたいこと | 読みでの予想 |
|---|---|---|
| 無音（何も鳴らさない） | デジタル出力の底。0 が並ぶか | ― |
| エレメントの音量 127 と 64 | 音量の目盛り | **12dB の差**（高さの表は音量が半分で 0x20、チップは 0x10 = 6dB、という読み） |
| リバーブへの送りを 127 と 64（エフェクトは切ったまま、送りだけ変える）| 送りの目盛り | 6dB の差。ただし音として出てこなければ、別のやり方に変える |
| 1 オクターブ上と下の鍵 | 音程の目盛り | 周波数がちょうど 2 倍・半分 |
| アタックの時間を 0・32・64・96・127 | EG の速さの目盛り | 8 目盛りで時間が半分。いちばん遅い値が約 19.8 秒なら、表の単位はサンプル数 |
| 和音（8 音を同時に） | 発音をずらす仕組み | 立ち上がりが最大 3 つの時刻に分かれる |

予想と違ったら、違ったほうが正しい。文書と骨組み（`src/motif/swp50.h`）を直す。

## 4. 波形の録音（長い。試しを 1 本やってから決める）

1. **試し**: 波形を 1 本だけ選び、雛形の音色で全部の鍵（128）を 1 秒ずつ鳴らして録る。約 3 分
2. 録ったものから、**鍵ごとにサンプルが切り替わる境目**が見つかるかを確かめる（隣の鍵と、音程を合わせたうえで波形の形を比べる）
3. 境目が見つかれば、区間ごとに真ん中の鍵で長く録る（ループが何周も入る長さ）
4. 2 と 3 の手間と時間を測ってから、全部の波形（1,859 本）をやるかを決める

全部を「全鍵 × 8 秒」で録ると約 22 日ぶん。境目を先に見つけてから録れば数日の桁、という見積もり。
プリセットが実際に使っている波形と鍵の範囲（2 で取った表）から先に録ると、早く役に立つ。

## 5. 記録の付け方

* 取ったファイルは `roms/motif-rack-es/capture/` に、日付と中身が分かる名前で置く
* 録音ごとに、送った MIDI ファイルを同じ名前で残す（あとで同じ条件をエミュレーターへ流せるように）
* 予想と結果は、この文書の 3 の表に列を足して書き込む
